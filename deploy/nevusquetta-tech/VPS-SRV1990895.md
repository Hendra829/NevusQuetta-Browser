## 4. Cara menjalankan

### 4.1 Di dalam VPS (sebagai root)

```bash
# 1. Salin direktori deploy/nevusquetta-tech/ ke VPS (lewat hPanel File Manager
#    atau unggah ZIP), lalu:
cd /path/ke/nevusquetta-tech

# 2. Jalankan konfigurasi Nginx + publickey
sudo bash install-vps.sh --kunci-publik "ssh-ed25519 AAAA... nevusquetta-deploy-20260928"

# 3. Unggah isi PWA ke webroot
sudo rsync -av public_html/ /var/www/nevusquetta.tech/
```

Skrip `install-vps.sh` melakukan, berurutan:

1. Memeriksa prasyarat (root, berkas sumber, nginx, certbot).
2. Memastikan sertifikat TLS ada — bila belum, menerbitkannya dengan certbot
   webroot. **Bila sertifikat tidak dapat diperoleh, nginx TIDAK diubah.**
3. Memasang snippet header keamanan ke `/etc/nginx/snippets/`.
4. Memasang konfigurasi situs, **menyesuaikan direktif HTTP/2 dengan versi
   nginx yang benar-benar terpasang**.
5. Menjalankan `nginx -t`. **Bila gagal: konfigurasi lama dipulihkan dan skrip
   keluar tanpa menyentuh nginx yang berjalan.**
6. Menambahkan kunci publik ke `authorized_keys` (idempoten — tidak menggandakan).
7. Reload nginx (atau menyalakannya bila belum berjalan).
8. Memverifikasi 3 URL kunci + 4 header keamanan + redirect www→apex.

Kode keluar: `0` sukses · `1` verifikasi gagal (sudah dipulihkan) · `2` prasyarat kurang.

### 4.2 Dari mesin lain (setelah kunci terpasang)

```bash
# Sinkronkan PWA
rsync -av --delete public_html/ root@nevusquetta.tech:/var/www/nevusquetta.tech/

# Atau lewat skrip yang sudah ada
./deploy-pwa.sh --metode rsync --host root@nevusquetta.tech --tujuan /var/www/nevusquetta.tech
```

## 5. Tiga bug nyata yang ditemukan dan diperbaiki

Ketiganya ditemukan dengan **menjalankan** konfigurasi, bukan membacanya.

### Bug 1 — `http2 on;` membuat `nginx -t` GAGAL di nginx < 1.25.1

```
$ nginx -t -c /tmp/ngxtest/nginx.conf
[emerg] unknown directive "http2" in .../nevusquetta.tech.conf:20
nginx: configuration file test failed
NGINX_T_EXIT=1
```

`http2 on;` hanya ada di nginx ≥ 1.25.1. Di nginx 1.22.1 (bawaan Ubuntu 22.04 /
Debian 12) direktif itu tidak dikenal → `nginx -t` gagal → **reload akan
mematikan situs**. Perbaikan: memakai bentuk `listen 443 ssl http2` yang bekerja
di 1.9.5 s/d 1.27.x, dan `install-vps.sh` menaikkannya ke `http2 on;` hanya bila
nginx ≥ 1.25.1.

### Bug 2 — header keamanan HILANG dari semua respons

```
$ curl -D - -o /dev/null -H 'Host: nevusquetta.tech' https://127.0.0.1/ | grep -i x-frame
(kosong)
```

Di nginx, `add_header` **tidak** bersifat menambah terhadap warisan: begitu
sebuah `location` punya `add_header` sendiri, ia berhenti mewarisi **seluruh**
`add_header` dari level `server`. Karena hampir semua berkas nyata cocok dengan
location ber-`add_header`, header keamanan hilang di mana-mana. Perbaikan:
dipindah ke `snippets/security-headers.conf` dan di-`include` di **setiap**
location yang memakai `add_header`.

### Bug 3 — `manifest.json` disajikan sebagai `application/json`

`default_type` tidak cukup: `mime.types` sudah memetakan `.json` →
`application/json`, dan `default_type` hanya dipakai bila tipe tidak dapat
ditentukan. Perbaikan: blok `types { }` kosong dikosongkan lebih dulu.

## 7. Yang belum terverifikasi / masih terblokir — tegas

1. **Sinkronisasi ke VPS srv1990895 BELUM dijalankan.** Tidak ada kredensial
   (SSH/FTP/API). Semua uji di atas dijalankan di **sandbox**, bukan di VPS.
2. **`install-vps.sh` belum pernah dijalankan di VPS sungguhan.** Yang terbukti:
   berjalan end-to-end di sandbox Debian 12 dengan nginx 1.22.1.
3. **Sertifikat TLS di VPS belum diperiksa.** Sandbox memakai sertifikat
   self-signed; penerbitan certbot di VPS belum diuji.
4. **`nevusquetta.tech` masih menyajikan halaman placeholder lama** (349 byte,
   `Last-Modified: Sat, 19 Sep 2026 10:52:28 GMT`). PWA belum terunggah.
5. **`/download/` yang ditautkan halaman lama masih 404.**
6. **Pemasangan PWA di perangkat belum diuji** — butuh domain terisi + Chrome Android.
7. **`beforeinstallprompt` belum pernah teramati.**
8. **Versi nginx di VPS srv1990895 belum diketahui** — skrip menanganinya secara
   otomatis, tetapi cabang mana yang akan terpakai belum dapat dipastikan.
9. **`ssl_stapling` memunculkan peringatan** pada sertifikat self-signed
   ("issuer certificate not found"). Dengan sertifikat Let's Encrypt asli
   peringatan ini seharusnya hilang, tetapi **belum diverifikasi**.
10. **`deploy-pwa.sh` metode `rsync`/`scp`/`ftp` belum pernah dijalankan sampai
    selesai** — hanya metode `lokal` yang diuji nyata.
