## 2. Verifikasi jalur gagal-tertutup (fail-closed)

Pertanyaan inti: **ketika libsodium TIDAK tersedia, apakah verifikasi menolak —
dan apakah ada jalur yang diam-diam menerima?**

### 2.1 `Ed25519Verify()` — semua jalur keluar diperiksa

Seluruh `return` di dalam `Ed25519Verify()` diperiksa satu per satu. Tidak ada
`return true` yang dapat dicapai tanpa verifikasi nyata:

- panjang kunci ≠ 32 → `false`
- panjang tanda tangan ≠ 64 → `false`
- `message == nullptr && message_len > 0` → `false` (tidak ada deref null)
- pemeriksaan bentuk `y < p` dan `S < L` dijalankan **lebih dulu di kedua mode**
- tanpa `NQ_HAVE_LIBSODIUM` → `return false` (gagal-tertutup)
- dengan libsodium → `crypto_sign_verify_detached(...) == 0`

### 2.5 Jalur integrasi ruleset

`nq_ruleset.cpp` memverifikasi dalam urutan **checksum dulu, tanda tangan
kemudian**. Bila `declared_signed == true`:

- blok `signature` tidak ada → `kSignatureMissing`
- `options.verifier == nullptr` → `kSignatureAlgorithmUnsupported`
- algoritma tidak cocok → `kSignatureAlgorithmUnsupported`
- verifikasi gagal → `kSignatureInvalid`

Bila `declared_signed == false` dan `allow_unsigned == false` → `kUnsignedRejected`.
Tidak ada jalur yang melewati verifikasi.

`Ed25519SelfTest()` dipanggil saat startup di `cef_app_main.cpp:82`, sehingga
backend yang tidak berfungsi terdeteksi lebih awal.

## 3. Temuan

### T1 — Tidak ada uji jalur POSITIF lewat `Ed25519RulesetVerifier::Verify()`
**Tingkat: SEDANG.** Uji yang ada memanggil `Ed25519Verify()` langsung. Verifier
konkret (`Ed25519RulesetVerifier`) — yang memetakan `algorithm()` dan memanggil
`Verify()` — **tidak pernah diuji pada jalur sukses**. Artinya: bila pemetaan
algoritma atau penerusan argumen di kelas itu salah, uji saat ini tetap lulus.
**Rekomendasi:** tambahkan satu uji yang memuat ruleset bertanda tangan sah
lewat `LoadRuleset()` dan menegaskan `kOk`. Dapat dikerjakan sebagai PR lanjutan;
**tidak menghalangi merge** karena jalur primitifnya sudah terbukti benar.

### T2 — Workflow CI belum pernah dijalankan di GitHub Actions
**Tingkat: RENDAH.** YAML sah (`actionlint` exit 0) dan langkah-langkahnya
dijalankan manual di sandbox, tetapi hasil run CI sebenarnya belum ada.
**Rekomendasi:** jalankan setelah merge; bila gagal, perbaiki di PR terpisah.

### T3 — Belum ada pemeriksaan versi minimum libsodium
**Tingkat: RENDAH.** Yang dipakai libsodium 1.0.18 (Debian 12). CMake hanya
memeriksa keberadaan pustaka, bukan versinya. **Rekomendasi:** tambahkan
`find_package` versi minimum bila kelak memakai API yang lebih baru.

### T4 — Belum ada jalur pembangkitan tanda tangan
**Tingkat: SEDANG (untuk rilis).** Verifier sudah benar, tetapi belum ada alat
untuk **membuat** tanda tangan beserta prosedur penyimpanan kunci privat.
Tanpa ini, ruleset produksi belum dapat ditandatangani dengan aman.
**Rekomendasi:** PR terpisah sebelum rilis bertanda tangan.

### T5 — Komentar basi pada `nq_assets_test.cpp`
**Tingkat: RENDAH.** Sebagian komentar menyebut kondisi yang sudah diperbaiki
di `main`. Tidak memengaruhi perilaku. **Rekomendasi:** rapikan saat menyentuh
berkas itu lagi.
